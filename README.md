# 净记 PWA

当前版本 **1.1.0**。本项目后续只维护 PWA。

无需 App Store、开发者会员或每 7 天重新签名。部署为 HTTPS 静态网站后，可在 iPhone Safari 中“添加到主屏幕”，首次打开并完成离线缓存后即可离线使用。

GitHub Pages 地址：<https://allenchangchang.github.io/jingji-pwa/>。
源码仓库：<https://github.com/allenchangchang/jingji-pwa>。

## 功能

- 消费、收入、退款、转入、转出，退款自动关联原消费并按原月份抵扣。
- 退款金额使用灰色剩余可退金额；留空为全额退款，直接输入为部分退款。
- 多级父账单、合并记录、逐笔输入金额并自动计算总额。收入单独汇总，按月或自定义日期筛选。
- IndexedDB 本地存储，无账号、无服务端、不上传账单。
- Service Worker 离线启动。
- 新备份使用 JSON v3，完整保留多级目录；仍支持读取原生 v1/v2 备份。
- 导入前保留上一份账本，可在设置中恢复。
- 已有本地 v1/v2 账本首次保存为 v3 前，自动保留原账本，可从设置导出。

## 多级账单、合并与退款

1. **一次输入多笔金额**：点“记一笔 → 连续输入多笔金额”，逐行填写金额，可选填每笔名称，点“再输入一笔金额”继续添加。总金额实时计算，保存后组成一张父账单。各笔继承本次表单的日期、类型、分类和渠道，之后可单独编辑。
2. **合并已有记录**：在流水中点“选择账单合并”，点击同一目录里的两项或更多账单，点“合并所选”并填写父账单名称。已有父账单也能继续合并；在父账单里可添加子账单，或选择子账单再合并成下一层。
3. **保留原日期**：合并不改写原记录的 ID、金额、日期、渠道、分类和退款关系。父账单显示整单金额，首页月度统计仍按每笔原日期归属，金额只统计一次。
4. **消费与退款**：消费及这些消费自己的退款可放在同一父账单；父账单显示净花费。所有已关联退款都会计入净额，目录外的关联退款会在详情中列明。收入、转出、转入等保持同类型合并。
5. **直接退款**：打开消费父账单点“退款”，立即弹出当前账单内可退款的子消费目录，包含层级路径、原日期和剩余金额。点击一笔进入退款表单；金额留空按该笔剩余金额全额退款，输入金额则部分退款。新退款自动加入原消费所在目录，已退完的消费不再出现在选择目录里。
6. **取消合并**：父账单可重命名，也可“取消这一级合并”。取消仅拆开目录，全部原记录及退款关系保留。删除原消费仍要求先处理关联退款。

父账单最多 8 层，每个目录最多 100 项；一次最多输入 100 笔金额。输入金额按整数分计算，不能通过负数金额替代退款。旧版已有拆分明细原样保留。

## 本地运行与验证

不能直接双击 `index.html`，Service Worker 和 ES Modules 需要 HTTP/HTTPS。进入包含 index.html 的目录（此独立仓库根目录，或原生项目的 PWA 目录）运行：

```sh
npm test
python3 -m http.server 4173
```

浏览器打开 `http://127.0.0.1:4173/`。localhost 可测试离线能力；iPhone 安装必须使用 HTTPS 地址。

## 免费部署

整个 `PWA/` 目录是静态站点，没有构建步骤。任选一个支持 HTTPS 的免费静态托管：

### GitHub Pages

本目录就是待发布仓库的根目录，包含 `.nojekyll`，无需构建或 Jekyll。默认仓库名为 `jingji-pwa`。

1. 在 Mac 安装 GitHub CLI 并登录：`gh auth login --hostname github.com --git-protocol https --web`。密码和验证码只在 GitHub 官方页面输入。
2. 在 GitHub 登录账号下新建公开仓库 `jingji-pwa`，将本目录提交到 `main` 分支后推送。
3. 仓库 Settings → Pages → Deploy from a branch，选择 `main` 和 `/ (root)`。
4. 等待 Pages 部署成功，用 Safari 打开 `https://<用户名>.github.io/jingji-pwa/`。需确认首页、`manifest.webmanifest`、`sw.js` 和两个图标均能正常访问，再添加到主屏幕。

免费 GitHub Pages 使用公开仓库。只发布本目录的 PWA 源码、说明和合成测试夹具，不上传原生 App 构建产物、个人账本或备份。

后续更新继续推送同一仓库的 `main` 分支，Pages 会自动发布；修改应用资源时同步更新 `sw.js` 的缓存版本。保持仓库名和网址不变，以便继续访问本机已有账本。版本回滚通过新的 Git 提交恢复旧文件后推送，发布前先导出账本备份。

GitHub Pages 仓库可以公开；账本不会进入仓库，账本只存在访问者手机的 IndexedDB 中。代码公开不等于账单公开。

### Cloudflare Pages / Netlify

直接上传本目录或 `JingJi-PWA-1.0.0.zip` 的解压内容，构建命令留空，输出目录为根目录。平台提供的 HTTPS 域名即可安装。

## 安装到 iPhone

1. 用 Safari 打开部署后的 HTTPS 地址，等待首页显示。
2. Safari 底部“分享” → “添加到主屏幕”。
3. 打开“作为网页 App 打开”，点“添加”。
4. 从桌面启动一次。之后没有 7 天过期限制，离线也可记账。

首次缓存必须联网。若更换域名，浏览器会视为另一个 App，需先从旧地址导出备份，再在新地址恢复。

## 从原生版迁移

1. 原生净记：设置 → 导出账本备份。
2. PWA：设置 → 从原生版或 PWA 备份恢复。
3. 选择 JSON 文件并确认。日期、金额、退款关系、收入和子账单都会保留。导入成功后关闭设置页，自动展示覆盖整个账本日期范围的全部类型记录，并清空原搜索条件。

尚未导入时，首页空账本可直接点“导入原生 App 账本”。若已经导入但当前月份或筛选条件下为空，首页会显示账本总笔数，点“查看全部记录”即可看到历史月份、收入和转账。之后可通过日期选择恢复月度统计。

两个版本不会自动同步。切换前先导出备份，确认 PWA 数据正确后再决定是否继续使用原生版。

原生 App 打不开、也没有备份时，请保留原 App 并连接安装时使用的 Mac，先尝试取出原 App 数据目录中的账本。如果需要刷新签名，使用原来的 Apple Team 和 App 标识覆盖安装后再导出，不要先卸载。PWA 无法直接访问原生 App 的私有数据目录。原生版不再同步开发新功能，新的 v3 备份不能恢复到旧原生版。

## 版本升级与回退

更新后联网关闭并重新打开 PWA，在设置底部确认“净记 PWA 1.1.0”。保持同一网址，不清理网站数据。

已有本地 v1/v2 账本只读取时不改写；首次保存 v3 前先备份完整旧账本，备份失败会阻止覆盖。设置中可以“导出多级升级前的账本”，之后导入此备份可恢复升级前的数据。升级前备份不包含升级后新增的记录，请先另外导出当前 v3 备份。回退旧代码前需先恢复旧格式账本；旧版 PWA 和旧原生 App 无法读取 v3。

## 数据安全与限制

- 数据只在当前 HTTPS 域名和当前设备的浏览器存储中。
- 删除主屏幕 Web App、清理 Safari 网站数据、系统存储回收或更换域名，都可能导致本地数据不可用。
- 定期导出 JSON 到“文件”或 iCloud Drive。PWA 会请求持久存储，但 iOS 是否批准由系统决定。
- 本版本不包含云同步、登录、微信/支付宝个人账单 API 或后台自动导入。
- 更新代码时需修改 `sw.js` 的 `CACHE` 版本，确保设备取得新资源。
